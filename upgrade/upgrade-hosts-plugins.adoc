= Upgrade SnapCenter plug-ins and hosts
:icons: font
:imagesdir: ./media/

[.lead]
Before you upgrade SnapCenter plug-ins, install the required Java, .NET, and PowerShell versions on the SnapCenter Server and plug-in hosts, and then upgrade the SnapCenter Server and each plug-in.

There are two options you can follow based on your environment and upgrade requirements.

|===
| *Option* | *When to use* | *User stops services?*
| 
*Plug-in upgrade from SnapCenter* | You upgrade the plug-in from SnapCenter UI / workflow | *No* - SnapCenter manages service stop/start
| 
*Component-only upgrade* | You change only Java / .NET / PowerShell (for example CVE); plug-in version stays the same | *Yes* - User must stop and start services manually
|===

.Before you begin
For both available options, do the following:

* Put hosts into maintenance mode 
* Verify that the hosts are healthy after the upgrade
* Take hosts out of maintenance mode

NOTE: Do not remove older Java / .NET / PowerShell versions until the host is healthy with the new versions.

== Plug-in upgrade from SnapCenter

.Steps
. Place all affected hosts in maintenance mode.
. Prepare prerequisites before the plug-in upgrade (install side by side; do not remove the old version yet):
.. Java 17 — set `JAVA_HOME` to Java 17; verify that the command `java -version` shows version as 17 (On Windows, if the registry default is still Java 11, the upgrade might fail even when Java 17 is installed.)
.. .NET/PowerShell as required by your SnapCenter release
. From SnapCenter, upgrade the plug-in on the host.
. Confirm the host and services are healthy in SnapCenter.
. Remove unused older components only if they are not needed by anything else.
. Take hosts out of maintenance mode.

[NOTE]
=========================================
* You do not need to manually stop SPL/SCC/PluginCreatorService or use `pkill`.
* SnapCenter plug-in upgrade handles the service lifecycle.
* If the host is not prepared correctly (for example, wrong Java/JAVA_HOME), the upgrade might fail or services might not start after upgrade.
=========================================

== Component-only upgrade (no plug-in upgrade)

.Steps
. Place all affected hosts in maintenance mode.
. Stop SnapCenter plug-in services (see below).
. Clear stale processes if the stop process did not clean them up.
. Install the new Java / .NET / PowerShell versions and update the configuration as needed (for example, set `JAVA_HOME`).
. Start the SnapCenter plug-in services.
. Confirm the host status and services in SnapCenter.
. Remove unused older components only if they are not needed by anything else.
. Take hosts out of maintenance mode.

=== Stop services before the upgrade
.Linux/AIX
. `/opt/NetApp/snapcenter/spl/bin/spl stop`
. `/opt/NetApp/snapcenter/scc/bin/scc stop`
. Check: `ps -ef | grep -i snapcenter`
. If stale processes remain:
	.. `pkill -f scAgent`
	.. `pkill -f '/opt/NetApp/snapcenter/spl'`
	.. `pkill -f '/opt/NetApp/snapcenter/scc'`
. Recheck with `ps -ef | grep -i snapcenter` before continuing.

.Windows
. Run `Stop-Service -Name PluginCreatorService -Force`
. Confirm the service is stopped.
. Stop any remaining Java / agent processes before continuing.

=== Start services after the upgrade
.Linux/AIX
. `/opt/NetApp/snapcenter/spl/bin/spl start`
. `/opt/NetApp/snapcenter/scc/bin/scc start`

.Windows
. Run `Start-Service -Name PluginCreatorService -Force`

Install the new versions on the SnapCenter Server and on each plug-in host before you upgrade any plug-in. Leave the currently installed Java and .NET in place.


== Process checklist

====

.Plug-in upgrade

--
. Hosts placed in maintenance mode
. Prerequisites ready (Java 17 + JAVA_HOME, .NET, PowerShell as required)
. Plug-in upgraded from SnapCenter
. Host verified
. Old unused components removed only after verification
. Hosts taken out of maintenance mode
--

.Component-only upgrade
--
. Hosts placed in maintenance mode
. Services stopped; stale processes cleared (`pkill` on Linux/AIX if needed)
. New component installed and configured
. Services started
. Host verified
. Old unused components removed only after verification
. Hosts out of maintenance mode
--
