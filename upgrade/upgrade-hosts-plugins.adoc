= Upgrade SnapCenter plug-ins and hosts
:icons: font
:imagesdir: ./media/

[.lead]
You can upgrade SnapCenter plug-ins from SnapCenter, or you can upgrade only the Java, .NET, or PowerShell components on a host without changing the plug-in version. Choose the option that fits your environment, and put the hosts in maintenance mode before you start.

[options="header"]
|===
| Option | When to use | Do you stop and start the services manually?
| Plug-in upgrade from SnapCenter | You upgrade the plug-in by using the SnapCenter user interface. | No. SnapCenter stops and starts the services.
| Component-only upgrade | You change only Java, .NET, or PowerShell (for example, to address a CVE). The plug-in version stays the same. | Yes. You must stop and start the services.
|===

NOTE: Keep the older Java, .NET, and PowerShell versions installed until you verify that the host is healthy with the new versions.

== Plug-in upgrade from SnapCenter

.Steps
. Place all affected hosts in maintenance mode.
. Prepare prerequisites before the plug-in upgrade (install side by side; do not remove the old version yet):
.. Java 17 — set `JAVA_HOME` to Java 17; verify that the command `java -version` shows version as 17 (On Windows, if the registry default is still Java 11, the upgrade might fail even when Java 17 is installed.)
.. .NET andPowerShell as required by your SnapCenter release.
. From SnapCenter, upgrade the plug-in on the host.
. Confirm the host and services are healthy in SnapCenter.
. Uninstall the older Java, .NET, and PowerShell versions if no other application on the host requires them.
. Take hosts out of maintenance mode.

[NOTE]
=========================================
* You do not need to manually stop the SnapCenter Plug-in Loader (SPL), SnapCenter Plug-in Creator (SCC), or `PluginCreatorService` services, or use `pkill`.
* The SnapCenter plug-in upgrade stops and starts the services for you.
* If the host is not prepared correctly (for example, wrong Java version or `JAVA_HOME`), the upgrade might fail or services might not start after the upgrade.
=========================================

== Component-only upgrade (no plug-in upgrade)

.Steps
. Place all affected hosts in maintenance mode.
. Stop the SnapCenter plug-in services as described in <<stop-services,Stop services before the upgrade>>.
. Clear stale processes if the stop process did not clean them up.
. Install the new Java, .NET, and PowerShell versions and update the configuration as needed (for example, set `JAVA_HOME`).
. Start the SnapCenter plug-in services as described in <<start-services,Start services after the upgrade>>.
. Confirm the host status and services in SnapCenter.
. Uninstall the older Java, .NET, and PowerShell versions if no other application on the host requires them.
. Take hosts out of maintenance mode.

[[stop-services]]
=== Stop services before the upgrade
Stop the SnapCenter plug-in services on the host before you install the new Java, .NET, or PowerShell versions.

.Steps for Linux and AIX hosts
. Run the following commands on the plug-in host:
.. `/opt/NetApp/snapcenter/spl/bin/spl stop`
.. `/opt/NetApp/snapcenter/scc/bin/scc stop`
. Check for remaining SnapCenter processes by running `ps -ef | grep -i snapcenter`.
. If stale processes remain, run the following commands:
.. `pkill -f scAgent`
.. `pkill -f '/opt/NetApp/snapcenter/spl'`
.. `pkill -f '/opt/NetApp/snapcenter/scc'`
. Run `ps -ef | grep -i snapcenter` again to confirm that no SnapCenter processes remain before you continue.

.Steps for Windows hosts
. In PowerShell on the plug-in host, run `Stop-Service -Name PluginCreatorService -Force`.
. Confirm that the service is stopped.
. Stop any remaining Java and agent processes before you continue.

[[start-services]]
=== Start services after the upgrade
After you install and configure the new Java, .NET, or PowerShell versions, start the SnapCenter plug-in services on the host.

.Steps for Linux and AIX hosts
. Run the following commands on the plug-in host:
.. `/opt/NetApp/snapcenter/spl/bin/spl start`
.. `/opt/NetApp/snapcenter/scc/bin/scc start`

.Steps for Windows hosts
. In PowerShell on the plug-in host, run `Start-Service -Name PluginCreatorService`.

== Process checklist

[role="tabbed-block"] 
====

.Plug-in upgrade

--
. Place the hosts in maintenance mode.
. Install the prerequisites side by side: Java 17 with `JAVA_HOME` set, and .NET and PowerShell as required.
. Upgrade the plug-in from SnapCenter.
. Confirm the host and services are healthy.
. Uninstall the older Java, .NET, and PowerShell versions if no other application on the host requires them.
. Take the hosts out of maintenance mode.
--

.Component-only upgrade
--
. Place the hosts in maintenance mode.
. Stop the services and clear stale processes (use `pkill` on Linux and AIX if needed).
. Install the new Java, .NET, and PowerShell versions and update the configuration.
. Start the services.
. Confirm the host and services are healthy.
. Uninstall the older Java, .NET, and PowerShell versions if no other application on the host requires them.
. Take the hosts out of maintenance mode.
--
====

[NOTE]
======
* The .NET and PowerShell versions to use are specified in the latest link:https://library.netapp.com/ecm/ecm_download_file/ECMLP3359467[SnapCenter Release Notes^].
* For a plug-in upgrade, use the Java version supported by the target SnapCenter release. For a component-only upgrade, use the Java version supported by the installed release. SnapCenter 6.2.1 and later require Java 17; SnapCenter 6.2 and earlier require Java 11. 
* Use your site install path if it differs from `/opt/NetApp/snapcenter`.
======
